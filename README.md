# Стрибог - модуль CrypTool 2

Реализация хэш-функции ГОСТ Р 34.11-2012 (Стрибог) в виде отдельного компонента CrypTool 2.

## Возможности

- Хэш 256 и 512 бит.
- Необязательный вход IV.
- Стандартный IV при неподключённом или пустом входе IV:
  - 512 бит: `00…00`;
  - 256 бит: `01…01` в каждом байте.
- Два выхода: `byte[]` и `ICrypToolStream`.
- Пошаговая презентация: `IV`, `h`, `N`, `Σ`, `m`, `data`, `K`, раунды `g`, финализация.
- Просмотр таблиц `S`, `P`, `L` (`Pi`, `Tau`, `A`).
- Соответствие контрольным векторам RFC 6986 для 256 и 512 бит.

## Установка

### Вариант 1 

1. Закрыть Cryptool2.
2. Скопировать `bin/Streebog.dll` в:

```text
%LOCALAPPDATA%\CrypTool2\CrypToolStore\Release\plugins\
```

Если папки `Release` нет, а есть `Developer`, использовать `Developer`.

3. Запустить CrypTool 2 и добавить компонент `Стрибог` в рабочую область.

### Вариант 2

1. Закрыть Cryptool2.
2. Скопировать `bin/Streebog.dll` в:

```text
C:\Program Files\CrypTool 2\CrypPlugins\
```

Требуются права администратора.

3. После копирования запустить CrypTool 2 и добавить компонент `Стрибог` в рабочую область.

## Сборка

Требования:

- Windows.
- .NET Framework 4.x.
- Установленный CrypTool 2 с файлом `CrypPluginBase.dll`.
- PowerShell.

Базовая сборка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Результат:

```text
bin/Streebog.dll
```

Если CrypTool 2 установлен не в папку по умолчанию:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Ct2Dir "D:\CrypTool 2"
```

Сборка с установкой для текущего пользователя:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Install
```

Сборка с установкой для всех пользователей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -InstallMachine
```

Перед установкой закрыть Cryptool2, иначе DLL будет занята.

## Использование

1. Добавить компонент `Стрибог`.
2. Подключить источник данных к входу `Входные данные`.
3. В настройках выбрать размер хэша: `256 бит` или `512 бит`. По умолчанию — `512 бит`.
4. При необходимости подключить к входу `Вектор инициализации (IV)` поток ровно из 64 байт.
5. Запустить вычисление.

Если вход IV не подключён или содержит пустой поток, используется стандартный IV для выбранного размера хэша. Если поток IV содержит не 64 байта, вычисление прерывается ошибкой.

Байты IV задаются в порядке следования в хэше; внутри они разбираются как восемь 64-битных слов little-endian.

Презентация по умолчанию останавливается на каждом шаге. Для непрерывного вывода используй `Авто`, для вычисления без пошагового просмотра — `Пропустить всё`.

## Входы и выходы

| Порт | Тип | Назначение |
|---|---|---|
| `Входные данные` | `ICrypToolStream` | Данные для хэширования |
| `Вектор инициализации (IV)` | `ICrypToolStream` | Необязательный IV, 64 байта |
| `Выходные данные` | `byte[]` | Хэш: 32 или 64 байта |
| `Выходной поток` | `ICrypToolStream` | Тот же хэш в виде потока |

Байты результата выдаются в том же порядке, в котором отображается HEX в презентации.

## Структура

| Файл | Назначение |
|---|---|
| `Streebog.cs` | Компонент CrypTool 2, порты и жизненный цикл |
| `StreebogCore.cs` | Алгоритм ГОСТ Р 34.11-2012 и формирование шагов трассировки |
| `StreebogTables.cs` | Таблицы `C`, `Pi`, `Tau` и матрица `A` |
| `StreebogPresentation.cs` | WPF-презентация и просмотр таблиц |
| `StreebogSettings.cs` | Настройка размера хэша |
| `StreebogTraceStep.cs` | Снимок состояния алгоритма для презентации |
| `DetailedDescription/doc.xml` | Встроенная справка компонента |
| `build.ps1` | Сборка и установка |
